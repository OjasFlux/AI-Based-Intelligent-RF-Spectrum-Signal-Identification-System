# Processed Data

This directory contains the processed and prepared RadioML 2016.10a data used by the AI-based RF signal classification system.

The preprocessing pipeline converts the original dataset into NumPy arrays that can be directly loaded by the training, evaluation, and testing modules.

## 1. Processing Pipeline

```text
RML2016.10a_dict.pkl
        ↓
Load Dataset
        ↓
Extract IQ Signals
        ↓
Create Modulation Labels
        ↓
Create SNR Labels
        ↓
Encode Modulation Classes
        ↓
Normalize IQ Signals
        ↓
Train / Validation / Test Split
        ↓
Save NumPy Arrays
```

## 2. Generated Files

The directory contains the following processed files:

```text
processed/
├── X_train.npy
├── X_val.npy
├── X_test.npy
├── y_train.npy
├── y_val.npy
├── y_test.npy
├── snr_train.npy
├── snr_val.npy
├── snr_test.npy
└── modulation_classes.npy
```

## 3. Signal Data

The `X` files contain the processed IQ signal data.

```text
X_train.npy
    ↓
Training IQ signals

X_val.npy
    ↓
Validation IQ signals

X_test.npy
    ↓
Testing IQ signals
```

The original RadioML representation is:

```text
(2, 128)
```

where:

```text
2   → I and Q channels
128 → IQ samples
```

The preprocessing module preserves this signal representation for the saved processed datasets.

## 4. Labels

The `y` files contain the encoded modulation labels.

```text
y_train.npy
y_val.npy
y_test.npy
```

The labels are converted from modulation names into integer class IDs using `LabelEncoder`.

The class names are stored separately in:

```text
modulation_classes.npy
```

This allows the numerical prediction from the CNN to be converted back into the corresponding modulation name.

## 5. Modulation Classes

The project contains 11 modulation classes:

```text
8PSK
AM-DSB
AM-SSB
BPSK
CPFSK
GFSK
PAM4
QAM16
QAM64
QPSK
WBFM
```

The exact numerical class mapping is stored in:

```text
modulation_classes.npy
```

The mapping should always be used when interpreting model predictions.

## 6. SNR Data

The SNR files contain the SNR value associated with each signal:

```text
snr_train.npy
snr_val.npy
snr_test.npy
```

SNR information is retained because it is required for performance analysis.

It allows the project to evaluate:

```text
Classification Accuracy
        vs
SNR
```

This is particularly important for analyzing model performance under different signal-to-noise conditions.

## 7. Signal Normalization

Each IQ signal is normalized independently.

The magnitude is calculated as:

```text
Magnitude = √(I² + Q²)
```

The maximum magnitude of each signal is then used for normalization.

Conceptually:

```text
Original IQ
     ↓
Calculate Magnitude
     ↓
Find Maximum Magnitude
     ↓
Normalize I and Q
     ↓
Normalized IQ
```

A zero maximum magnitude is protected against division by zero.

## 8. Dataset Split

The preprocessing pipeline performs two stages of splitting.

### First Split

```text
80% → Training + Validation
20% → Testing
```

### Second Split

The 80% training-plus-validation portion is divided into:

```text
87.5% → Training
12.5% → Validation
```

Therefore, the final dataset proportions are:

```text
Training    → 70%
Validation  → 10%
Testing     → 20%
```

## 9. Purpose of Each Split

### Training Data

```text
X_train.npy
y_train.npy
snr_train.npy
```

Used to train the CNN.

### Validation Data

```text
X_val.npy
y_val.npy
snr_val.npy
```

Used during training to monitor model performance on data not used for weight updates.

### Testing Data

```text
X_test.npy
y_test.npy
snr_test.npy
```

Used for final model evaluation.

## 10. Data Usage

The processed data is used by different parts of the project.

```text
processed/
      │
      ├──► Training
      │
      ├──► Validation
      │
      ├──► Evaluation
      │
      └──► Prediction Testing
```

The processed data therefore acts as the connection between the dataset-preparation stage and the AI model stage.

## 11. How the Files Are Generated

The files are generated by:

```text
features/preprocessing.py
```

Run the preprocessing module from the project root:

```powershell
python features/preprocessing.py
```

The script:

```text
1. Loads the original dataset
2. Combines IQ signals
3. Creates labels
4. Encodes modulation classes
5. Normalizes IQ signals
6. Splits the dataset
7. Saves the processed arrays
```

## 12. Regenerating the Data

The processed files can be regenerated whenever the preprocessing pipeline needs to be rerun.

```powershell
python features/preprocessing.py
```

Running the preprocessing script recreates the `.npy` files using the current preprocessing configuration.

## 13. Important Note About the Dataset

The original RadioML dataset should be kept separately from the processed data.

The intended structure is:

```text
data/
├── dataset/
│   └── RML2016.10a_dict.pkl
│
└── processed/
    ├── X_train.npy
    ├── X_val.npy
    ├── X_test.npy
    ├── y_train.npy
    ├── y_val.npy
    ├── y_test.npy
    ├── snr_train.npy
    ├── snr_val.npy
    ├── snr_test.npy
    └── modulation_classes.npy
```

## 14. Data Reproducibility

The dataset split uses:

```text
random_state = 42
```

and stratified splitting.

This allows the same preprocessing procedure to reproduce the same train, validation, and test partitioning when the same source dataset and preprocessing code are used.

## 15. Data Integrity

The processed files should not be manually edited.

If preprocessing changes are required, modify:

```text
features/preprocessing.py
```

and regenerate the processed dataset.

This keeps the preprocessing procedure reproducible and documented.

## 16. Relationship With the CNN

The processed data is the input to the CNN training pipeline.

The overall flow is:

```text
Processed IQ
     ↓
CNN Input
     ↓
CNN
     ↓

```

The processed labels are used as the target output during training.

## 19. Storage Consideration

Processed NumPy files can be large because they contain the actual signal arrays.

For this reason, the project should consider whether generated processed data files should be committed directly to GitHub.

The repository can instead document how to regenerate them using:

```text
features/preprocessing.py
```

The original dataset may also have separate distribution or licensing requirements.

## 20. Recommended GitHub Practice

The repository should contain:

```text
data/processed/README.md
```

to explain the processed data.

Large generated files can be excluded from Git using `.gitignore` when appropriate.

For example:

```text
data/processed/*.npy
```

can be ignored if the team decides not to store generated arrays in the repository.

The exact Git strategy should be decided based on repository size and project requirements.

The `processed/` directory contains the machine-learning-ready representation of the RadioML 2016.10a dataset.
